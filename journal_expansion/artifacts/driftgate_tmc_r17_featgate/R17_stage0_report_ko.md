# Round 17 중간 보고서 1: checkpoint로 계산한 0단계 판정

이 보고서는 Round 17 지시문 4절(0단계)의 결과입니다. 새 학습은 하지 않았습니다. 지시문에 따라 1단계는 시작하지 않고 사용자의 확인을 기다립니다. 판정 기준과 분석 스크립트는 판정용 seed의 결과를 계산하기 전에 commit했습니다(`5cce14e`, `decision_rule.md`). 표의 값은 판정용 seed(S1 seed 1–4, S2 seed 0–2)의 평균(표준편차)이고, 차이는 같은 seed끼리 뺀 값입니다. 모든 표는 `tables/`에 CSV로 있습니다.

1차 후보는 설계용 seed에서 고른 R-b(D4)입니다. 두 설정 모두에서 두 조건이 미달이므로 판정은 `NO_GO`입니다(`decision_stage0.json`). 1차 후보가 아닌 R-b와 R-c(τ = ∞) 변형 가운데에도 B ≥ 0.5 pp를 만족한 것은 없습니다.

## 2. 시작 확인

Round 15의 재생 명령을 같은 flag로 다시 실행해 8개 재생 기록을 만들었습니다. 8개 모두 Round 15 재생 기록과 모든 출력 배열(예측, entropy, 확률, log 확률, 요청 정보)이 비트 단위로 같았습니다. DriftGate 정확도의 seed 평균은 S1 71.9467%, S2 76.5354%입니다. 표 A2의 71.95%와 76.54%와 0.05 pp 이내에서 같습니다(`R17_T0_start_check.csv`).

## 3. 구현에서 정한 것

- **runner 처리:** runner는 고치지 않았습니다. 평가 함수를 바깥에서 감싸 feature를 기록했습니다(`scripts/r17_extract.py`).
- **f_e의 정의:** f_e는 server exit(fc3)의 입력인 relu(fc2)이며 128차원입니다. server block을 거쳐 다시 계산한 출력은 server exit와 정확히 같았습니다(최대 차이 0). 두 cell에 속한 요청은 cell마다 f_e를 기록했습니다. S1 seed 0에서는 요청의 13.5%가 여기에 해당합니다.
- **통계에 쓴 표본:** 통계와 문턱은 학습 표본 전체로 만들었습니다. 이 checkpoint에는 validation 분리가 없으므로 결과가 낙관적일 수 있습니다. 평가 요청 가운데 Main 요청을 non-Main으로 판정한 비율은 다음과 같습니다(`R17_S0_detector_checks.csv`). 학습 표본으로 정한 설계값 α는 0.10입니다.
  - D1(α = 0.10): S1 0.268, S2 0.400
  - D2(α = 0.10): S1 0.106, S2 0.100
- **D1:** 공분산은 class 중심을 뺀 뒤 n으로 나누었고, ε = 10⁻³·trace(Σ)/128을 더했습니다.
- **D2:** 지시문에 k의 후보가 10 하나뿐이므로 k = 10으로 두었습니다. 학습 표본의 점수는 자기 자신을 뺀 나머지 표본으로 계산했습니다(leave-one-out).
- **설계용 seed에서 고른 값:** 설계용 seed(S1 seed 0)에서 R-b의 정확도로 α를 골랐습니다(`R17_S0_design.csv`).
  - D1의 α는 0.10입니다. R-b(D1)이 73.09%로, α = 0.05일 때의 72.93%보다 높았습니다.
  - D2의 α도 0.10입니다. R-b(D2)가 73.01%로, α = 0.05일 때의 72.90%보다 높았습니다.
  - 1차 후보는 R-b(D4)입니다. 7개 후보 가운데 73.29%로 가장 높았습니다.
- **D3:** 음성 표본은 home cell의 다른 거주 device가 가진 학습 표본 가운데 label이 M_k 밖인 것이고, **각 device 자신의 block(h_j)으로 만든 feature**입니다. 분류기는 scikit-learn 로지스틱 회귀이고, C = 1, class 비중 balanced, 표준화 없음으로 설정했습니다. S2에서는 거주 device가 1명인 cell의 device 1개가 음성 표본이 없어 head를 만들지 못했고, 그 device에서는 non-Main 판정을 하지 않았습니다.
- **D4:** 거주 device의 학습 표본으로 cell마다 원형을 만들었습니다. own class 원형이나 다른 class 원형이 그 cell에 없으면 점수를 정할 수 없으므로 non-Main 판정을 하지 않았습니다. 점수가 정의된 요청의 비율은 S1 0.897, S2 0.926입니다.
- **결합 가중치:** 모든 요청을 offload하는 규칙(R-b, R-s)은 DriftGate의 가중치를 썼습니다. 일부만 offload하는 규칙(R-a, R-c)은 같은 offload 집합에서 만든 Round 15의 DriftGate-P 가중치를 썼습니다.
- **거리 controller:** 직전 요청이 16개 미만이면 non-Main 판정만으로 offload했습니다. 실제 offloading 비율은 S2의 D3에서 0.488이었고, 나머지는 0.500이었습니다(`R17_S0_online.csv`).
