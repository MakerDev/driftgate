## 1. 판정

**판정은 "닫음"이다.** 기기 단위 조절과 요청 단위 조절 모두 진행 조건을 만족하지 못했다. 판정 값과 고른 설정은 `decision.json`에 있다.

판정은 후반 구간(평가 라운드 30–150)에서, 남긴 seed 세 개의 평균으로 했다. pp는 정확도 백분율의 차이다.

| 판정 항목 | 값 | 조건 | 결과 |
|---|---|---|---|
| D-SR − B3 | +0.76 pp (66.62% 대 65.86%) | 1.5 pp 이상 | 만족 못 함 |
| D-SR − G | +0.12 pp | 0.5 pp 이상 | 만족 못 함 |
| D-TV − B3 / D-TV − G | +0.69 pp / +0.04 pp | 1.5 pp / 0.5 pp 이상 | 만족 못 함 |
| R-결합 − B3 | −0.70 pp (65.16% 대 65.86%) | 2.0 pp 이상 | 만족 못 함 |
| D-oracle − B3 (참고) | +2.05 pp | 1.5 pp 미만이면 "상한부터 작다" | 상한은 1.5 pp 이상 |

규칙의 뜻은 다음과 같다.

- **결합 F(w, r)**: 답은 argmax [w·p_c + (1 − w)·p'_s]다.
  - p_c는 client exit의 확률, p'_s는 세기 r로 사전 확률을 보정한 server exit의 확률이다.
  - w는 client exit에 주는 비중이다.
- **B3**: 두 exit의 확률을 평균하는 규칙이며, F(0.5, 보정 없음)과 같다.
- **G**: 모든 기기에 같은 F(w, r)를 쓴다. 설정은 seed 교차 선택으로 골랐다. seed 교차 선택은 seed 하나를 남기고, 나머지 두 seed에서 가장 좋은 설정을 골라 남긴 seed에 적용하는 방법이다.
- **D-SR, D-TV**: 기기의 상태(집 또는 밖)를 신호로 판별하고, 상태마다 F(w, r)를 따로 쓴다.
  - 신호는 앞서 도착한 요청의 창에서 계산한다. x_SR은 server 예측이 학습 class 밖인 비율이고, x_TV는 두 exit 확률의 거리의 평균이다.
  - 문턱 θ와 상태별 설정은 seed 교차 선택으로 골랐다.
- **D-oracle**: 실제 at_home으로 상태를 나누고, 세 seed 전체에서 상태별 설정을 골랐다. 기기 단위 조절이 얻을 수 있는 몫의 상한이다.
- **R-결합**: 요청 하나의 특징 9개로 로지스틱 회귀를 학습해 P(Main)를 구하고, 이 값을 비중으로 두 exit를 섞는다.

## 6. 이득과 손실이 생긴 곳 (후반 구간, 표 1)

- **G와 B3의 차이**: G는 B3보다 0.64 pp 높다.
  - 집에서 +2.66 pp, Main 요청에서 +3.62 pp 높다.
  - 밖에서는 −0.61 pp, OOP에서 −4.96 pp, OOR에서 −2.60 pp 낮다.
  - 고른 설정은 세 seed 모두 server 쪽 비중이 큰 결합(w = 0.1–0.3)에 강한 보정(r = 0.5)이다.
- **D-SR과 G의 차이**: D-SR은 G보다 0.12 pp 높을 뿐이다.
  - 집(+0.20 pp)과 밖(+0.17 pp)의 차이가 모두 작다.
  - 상태 판별은 밖에 있는 요청의 42%만 "밖"으로 판별했다.
  - 문턱은 세 seed 모두 격자의 가장 큰 값(70번째 백분위수)이 골라졌다.
- **D-oracle과 B3의 차이**: D-oracle은 B3보다 2.05 pp 높다. 이득은 집(+4.83 pp)에서 나오고, 밖에서는 +0.44 pp에 그친다.

**결과를 보기 전에 정한 것**

1. **상태는 요청 단위로 정했다.**
   - 신호를 요청마다 앞선 요청의 창으로 계산하므로, 한 (클라이언트, 평가 라운드) 안에서도 요청마다 상태가 다를 수 있다. 지시문 4.2절은 한 상태에만 속한다고 적었지만, 이 구현에서는 그렇지 않다.
   - 그래도 상태마다 (w, r)를 따로 고를 수 있다. 정확도는 요청마다 1 / (그 클라이언트-라운드의 요청 수 × 클라이언트 수 × 평가 라운드 수)의 비중을 곱해 더한 값이기 때문이다.
2. **창이 없는 요청**: 첫 평가 라운드에서 앞선 요청이 8개 미만이면 "집 상태"로 두었다. 로지스틱 회귀의 특징 x_SR은 이때 0으로 두었다.
3. **θ의 후보**: 선택에 쓰는 두 seed의 모든 평가 라운드에서, 창이 있는 요청의 신호 값으로 백분위수를 구했다.
4. **자료형과 입력**
   - x_SR은 기록된 server exit 예측(logit의 argmax)으로 계산했다.
   - client exit의 entropy는 기록된 float32 값을 썼다.
   - server exit의 entropy, 두 exit의 확률, TV는 float16 확률로 계산했다.
5. **로지스틱 회귀**: scikit-learn의 기본 설정(L2 규제, C = 1, lbfgs)을 썼고, 반복 23–24번에 수렴했다. 학습에는 다른 두 seed의 후반 구간 요청 전부를 썼다.
6. **보정에 쓴 a**: Round 10과 같은 방법으로 만들었다(π_tr = 0.5·cell 분포 + 0.5·전체 분포, [0.01, 0.99]로 자름). a는 server exit가 학습할 때의 사전 확률 π_tr에서 학습 class(M_k)에 놓인 몫이다.
7. **GPU 공유**: 계산은 GPU 3에서 했고, 다른 프로젝트의 프로세스와 함께 썼다. 결과에는 영향이 없다.
