## 0. 이 보고서에서 쓰는 말

- **λ_t**: 학습에 쓰는 개인화 비율이다. arm 세 개는 λ_t를 고정한다.
  - T15: λ_t = 0.15
  - T40: λ_t = 0.4. Round 7의 F와 같은 학습이다.
  - T60: λ_t = 0.6
  - Λ는 모두 0.5다.
- **λ_inf**: 추론에만 쓰는 섞는 비율이다.
  - 평가 라운드마다 θ_inf = λ_inf·θ_local + (1 − λ_inf)·θ̄_Z를 client block으로 두고 평가했다. θ_local은 로컬 학습 직후의 client block이고, θ̄_Z는 그 라운드에 섞기에 쓴 cell 평균이다.
  - λ_inf 값은 0.15, 0.3, 0.4, 0.55, 0.7이다.
- **τ**: client exit의 entropy가 τ 이하이면 client exit의 예측으로 답을 끝내고, 넘으면 server exit의 예측을 쓴다. 지금까지는 τ = 0.8이었다.
- **server 사용 비율**: 평가 요청 가운데 server exit의 예측을 답으로 쓴 요청의 비율이다. 요청 수로 가중한다.
- **정확도**: 평가 라운드마다 클라이언트 정확도를 같은 비중으로 평균한 뒤, 평가 라운드 31개에서 평균한 값이다.
- **곡선**: τ를 0부터 2.30까지 0.05 간격으로 바꾸고 무한대(모든 요청을 client exit에서 끝냄)를 더하면, τ마다 (server 사용 비율, 정확도) 점이 하나 나온다. 이 점들을 이은 선이 곡선이다. 비교 지점의 값은 이웃한 두 점 사이를 선형 보간해 구한다.
- **B\***: T15, T40, T60에서 λ_inf = λ_t와 τ 하나만 쓰는 곡선 세 개를 만들고, 비교 지점마다 가장 높은 값을 고른 기준 곡선이다.
- **G**: 정책의 곡선과 B\*의 차이를 비교 지점 0.5, 0.7, 0.9에서 평균한 값이다.
  - seed마다 계산한 뒤 평균을 낸다.
  - [ ]는 Student-t 95% 신뢰구간이고, (a/3)은 G가 양수인 seed 수다.
- **pp**: 정확도 백분율의 차이다.
- **집과 밖의 판단**
  - oracle은 환경 파일의 at_home을 쓴다.
  - 신호 정책은 x_SR 또는 x_TV로 Round 7의 기기 단위 점수 q_k를 다시 계산한다. 라운드 1–25는 "집"으로 두고, 라운드 26부터 q_k ≥ 1.5이면 "밖"으로 둔다.
- **신호**
  - x_TV: probe 요청에서 client exit와 server exit 확률 벡터의 거리(TV)를 평균한 값이다.
  - x_SR: probe 요청 가운데 server exit의 예측이 클라이언트의 Main class 밖인 비율이다.
- **정책**
  - P1, P2, P3: 집에서는 λ_inf = 0.70, 밖에서는 λ_inf = λ_t를 쓰고, τ는 하나만 쓴다. 집과 밖은 각각 oracle, x_SR, x_TV로 정한다.
  - Q1, Q2, Q3: λ_inf = λ_t로 두고 집에서는 τ_home, 밖에서는 τ_away를 쓴다. 두 τ는 비교 지점마다 가장 좋은 조합을 고른다. 집과 밖은 P와 같은 방법으로 정한다.

## 3. 추가로 요청한 두 표 (판정에 쓰지 않음)

### 3.1 exit별 정확도 (`tables/v2_S1_exit_accuracy_mean.csv`)

- "client exit만"은 τ = 무한대, "server exit만"은 모든 요청을 server로 보낸 값이다.

  - 본 run 9개: 축약 파일의 τ = 0.8 값이 설치된 모델의 맞힌 수, server 사용 수와 모두 같았다. 정확도는 JSON과 소수 여섯째 자리까지 같다(`tables/v2_T1_checks.csv`).
  - 설치된 모델과 λ_inf = λ_t 블록의 요청별 출력이 다른 클라이언트-라운드는 9개 run 모두 0이었다.
- **probe 평균**: 요청별 probe 값의 평균과 x_TV, x_SR의 차이는 최대 1.1×10⁻⁷이다.
- **GPU 재현성** (`gpu_reproducibility_check.txt`): 같은 명령을 GPU에서 두 번 돌리면 손실이 최대 4.7×10⁻⁵ 다르다. 그래서 GPU run끼리는 bit 단위 동일성을 기대할 수 없다.
- **q_k 재계산**: 기록한 신호로 다시 계산한 q_k는 Round 7 기기 단위 run에 기록된 q_k와 2.4×10⁻⁷ 이내로 같았다. q_k ≥ 1.5 판단은 한 번도 다르지 않았다.
- **코드 동일성**: run 시작 시점과 종료 후를 비교하면 runner 코드는 같다. 달라진 파일은 분석 스크립트 하나다(6.4절의 10번).
  - 기록: `v2_code_identity_before.txt`(`db05747`), `v2_code_identity_launch.txt`(`a81d3da`), `v2_code_identity_after.txt`

### 6.4 불일치 기록과 구현에서 정한 것

1. **Round 8 첫 지시의 run**
   - 첫 지시(추론 비율만 보는 T40, T15 run 6개)는 2026-10-02 23:54에 띄웠다. 이 지시는 run 도중 지금의 지시로 바뀌었다.
   - 첫 지시의 run에는 요청별 기록이 없어 이번 판정에 쓸 수 없다. 남은 run이 이번 구현을 마치기 전에 끝나므로 그대로 끝까지 두었다.
   - 이 run은 `r8_*` 이름으로 기록에 남겼다. 같은 seed의 v2 run과 비교하면 차이는 −0.006 ~ +0.010 pp로, GPU 재현성의 크기를 보여 준다.
   - 첫 지시용 분석 스크립트(`scripts/r8_check_analysis.py`)는 돌리지 않았다.
2. **run 이름**: 이번 run은 `r8v2_<arm>_s<seed>`다. 첫 지시의 run 파일을 옮기거나 덮어쓰지 않으려고 이름을 바꿨다.
3. **T60의 설치된 모델**
   - λ_t 0.6은 λ_inf 목록에 없다. 그래서 T60에서는 설치된 모델의 요청별 출력을 여섯 번째 블록으로 기록하고, "λ_inf = λ_t"로 썼다.
   - T15와 T40은 λ_t가 목록에 있으므로 그 블록을 쓰고, 설치된 모델과 같은지 run 안에서 셌다(모두 0건 불일치).
4. **요청별 원본의 보관**
   - `*_requests.npz`(run마다 72–90 MB, 합계 약 720 MB)는 서버에만 두고 git에 넣지 않았다(`.gitignore`). sha256과 크기는 manifest에 있다.
   - git에는 이 원본에서 `scripts/r8v2_reduce.py`와 `r8v2_supplement.py reduce`로 만든 축약 파일(`reduced/`)을 넣었다. 축약 파일에는 클라이언트·라운드·τ별 맞힌 수와 server 사용 수, 종류별 개수가 들어 있다. 보고서의 모든 수치는 이 축약 파일과 run 원본에서 다시 계산할 수 있다.
5. **"두 예측이 맞았는지"**: 요청마다 정답 class를 저장했고, 맞았는지는 예측과 정답을 비교해 계산한다.
6. **τ 비교의 자료형**: run과 같게 float32로 비교했다(entropy ≤ τ이면 client exit). 그래서 τ = 0.8의 재계산이 설치된 모델 값과 정확히 같다.
7. **τ를 두 개 쓰는 곡선의 값**: 비교 지점마다 다음 두 방법 가운데 큰 값을 쓴다.
   - τ_home을 고정하고 τ_away 방향으로 보간한다.
   - τ_away를 고정하고 τ_home 방향으로 보간한다.
   - 지시문의 "모든 (τ_home, τ_away) 조합 가운데 정확도가 가장 높은 값"을 이웃한 두 점 사이의 선형 보간과 함께 구현한 것이다.
8. **probe 비용의 모델**
   - probe는 클라이언트의 요청 가운데 무작위로 뽑은 일부로 본다. 처음 m개는 무작위로 뽑은 순서의 앞부분이다.
   - 그 비율 min(probe 수, m)/N만큼의 요청은 그 클라이언트-라운드에 쓴 블록의 server exit로 답한다. 나머지 요청은 정책을 따른다.
   - 이때 server 사용은 실제 요청 수 N으로 가중하므로, B\*도 같은 가중으로 다시 계산했다.
   - 닿지 못하는 비교 지점은 G에서 빼고 닿는 지점만 평균했다. 닿는 지점은 표에 적었다.
9. **AUROC**: 각 arm 자신의 run에서 계산했다. Round 7은 F run만 썼다.
10. **분석 스크립트의 수정**
    - run을 띄운 뒤, 결과가 나오기 전에 두 곳을 고쳤다(`cce9c98`).
      - smoke 시험용 경로 지정
      - 그림 A의 범례 위치
    - 결과를 본 뒤에는 그림 B의 범례 위치만 고쳤고, 수치는 바뀌지 않았다.
    - 보조 표 스크립트에서 S1과 S2는 결과 전에 썼다. S3(무작위 표지와 같은 λ_inf)와 S4(시간대 분해)는 결과를 본 뒤에 더했다(4절).
11. **routing 상한의 가중**: 정확도가 클라이언트를 같은 비중으로 평균하므로, 요청 하나가 정확도에 주는 몫은 1/(그 클라이언트-라운드의 평가 요청 수)에 비례한다. 상한은 이 몫이 큰 요청부터 보내는 값이다.
12. **참여하지 않은 클라이언트**: S1에서는 모든 클라이언트가 매 라운드 참여해, 평가에서 빠진 클라이언트가 없다.
13. **T40과 Round 7 F**: 학습 명령은 같지만, GPU 연산이 bit 단위로 재현되지 않아 정확도가 +0.01–0.03 pp 다르다.
14. **정확도와 server 사용 비율의 가중**: 지시문대로 정확도는 클라이언트를 같은 비중으로, server 사용 비율은 요청 수로 가중했다. 두 값의 가중이 다르다.
